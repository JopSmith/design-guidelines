# Conversation Memory Indicators

## 1. Intent (Why this exists)

Shows what information the system remembers. Gives users awareness and
control over stored data.

## 2. Context of Use

-   Use when:
    -   System stores user data across sessions
-   Avoid when:
    -   No memory is used

## 3. Core Behaviour (How it works)

-   Trigger:
    -   System stores or references memory
-   System Response:
    -   Display indicator or message
-   Ongoing Behaviour:
    -   Update when memory changes
-   Exit Condition:
    -   User dismisses or edits memory

## 4. Rules & Constraints

-   MUST:
    -   Clearly indicate stored information
-   SHOULD:
    -   Allow user control
-   MUST NOT:
    -   Hide stored data usage

## 5. Variants

-   Variant A: Passive Indicator
-   Variant B: Editable Memory Panel

## 6. Examples (Abstract, not visual)

-   System saves preference
-   Shows "Preference saved"
-   User edits memory

## 7. Rationale (Why it works)

-   Builds trust
-   Improves transparency

## 8. Trade-offs

-   Pros:
    -   User control
-   Cons:
    -   Additional complexity
