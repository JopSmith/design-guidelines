# Dialog

## 1. Description

A Dialog is a container or box that presents focused content or actions in a layer above the main interface. They are commonly used to display important information, request input, or confirm decisions without navigating away from the current context. Dialogs typically include a clear title, supporting content, and one or more actions. They often use contextual colours to communicate intent, such as neutral for general information, positive for success, warning for caution, or destructive for high-risk actions.

Dialogs can be either **modal** (require the user to interact with them before returning to the main interface) or **non-modal** (allow interaction with the underlying content while remaining visible).

## 2. Usage

### When to Use

Use a Dialog when you need to interrupt the normal flow to focus the user on a specific task, decision, or piece of information. Modal dialogs are appropriate for critical confirmations, irreversible actions, or required inputs. Non-modal dialogs are better suited to supplementary information or secondary tasks that should not block progress.

### Do
- Keep the interface focused by showing one dialog at a time
- Keep dialogs focused and concise, including only essential information or actions
- Use dialogs for focused, simple interactions or brief confirmations that require minimal user input
- Ensure the dialog body handles scrolling, allowing users to navigate content smoothly without nested scrollbars
- Trap focus within the dialog while it's open
- Ensure keyboard and screen-reader accessibility
- Provide a visible and accessible close icon/button
- Include a semi-transparent scrim behind the dialog
- Focus the first interactive element when the dialog opens
- Make dialog content scrollable only in the body if needed
- Maintain reasonable width and height for dialogs (responsive design)
- Return focus to the trigger element after the dialog closes
- Provide clear, labelled primary and secondary buttons
- Use the appropriate severity variant:
  - **Default** — for general messages or neutral content
  - **Primary** — for data capturing forms and key user inputs
  - **Success** — for positive confirmations, achievements, or helpful tips
  - **Danger** — for critical warnings and irreversible actions
  - **Warning** — for cautionary messages that require user attention
  - **Info** — for neutral informational notes or contextual guidance
- Use the **AI Aura** dialog style exclusively when the content has been generated by AI

### Don't
- Stack multiple dialogs on top of each other
- Overload dialogs with too much content — use a drawer or dedicated page instead
- Display data tables or complex information inside dialogs
- Allow individual components inside a dialog to scroll independently
- Nest dialogs inside other dialogs
- Rely solely on visual cues for interaction or feedback
- Prevent users from closing the dialog without a valid reason
- Let background content remain interactive while the dialog is open
- Overload dialogs with excessive content or complex workflows
- Allow nested scroll containers within the dialog
- Place large data tables, charts, or infinite content in dialogs
- Forget to manage focus when the dialog opens or closes
- Use ambiguous button labels like "OK" or "Submit" without context
- Use dialog severities inconsistently or out of context
- Use the AI Aura dialog style for manually written, static, or non-AI-generated content

## 3. Composition

The Dialog consists of the following accessories:

| Accessory | Required | Description |
|---|---|---|
| Title (Mandatory) | Mandatory | Displays the name of the dialog |
| Subtitle | Optional | Appears below the title and used for secondary text |
