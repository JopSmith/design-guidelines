# Icon

## 1. Description

An Icon is a small graphical symbol used to represent an action, object, or concept within an application. Icons enhance recognition, reduce cognitive load, and support quick scanning by providing visual cues. They should be simple, consistent, and meaningful, reinforcing the accompanying text or action rather than replacing it.

## 2. Usage

### When to Use

Icons are most commonly used to aid navigation, provide visual cues on buttons, or represent toolbar actions. Use icons to support and clarify meaning, not as a substitute for text. They work best when paired with clear labels to reinforce actions or content, helping users recognise functionality quickly.

Icons must be used consistently across all products to ensure familiarity and a unified visual language. Our icon provider is Icons8, and we currently use the **Windows 11** icon sets — **Outline**, **Filled**, and **Color**. Outline icons are primarily used in the shell for navigation, Filled icons are applied selectively for emphasis, and Color icons appear within page content to add visual interest.

### Do
- Use approved icons from the standard icon library to maintain consistency, familiarity, and alignment with the design system's visual language
- Use icons consistently across all products to build familiarity and reinforce a cohesive visual language
- Use unique and meaningful icons to clearly differentiate actions and concepts
- Pair icons with labels to clarify meaning and improve accessibility, especially for complex or unfamiliar actions
- Maintain consistent sizing and alignment to ensure visual balance across different components and layouts
- Use appropriate icon styles based on context and emphasis — Outline for navigation, Color within content
- Use icons sparingly to enhance recognition and scanning
- Use predictable icon sizing based on the 8px grid system (16px – 24px – 32px)
- Use both colour and an additional visual cue (such as a label or pattern) to indicate status

### Don't
- Create or use custom icons outside the established set
- Mix icons — e.g. don't use a cog for Settings in one screen but a wrench in another
- Reuse the same icon for multiple, unrelated actions
- Rely on icons alone to convey meaning unless they are universally recognised (e.g. search, close, settings)
- Stretch, distort, or rotate icons
- Mix icon styles within the same context or outside the usage guidelines
- Use Color icons arbitrarily, as this can distract users and reduce clarity of hierarchy or purpose
- Overuse icons where text alone provides clearer communication
- Use irregular or inconsistent icon sizes that don't align with the 8px grid
- Rely on colour alone to convey status or meaning
