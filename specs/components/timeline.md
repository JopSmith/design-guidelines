# Timeline

## 1. Description

A Timeline component is a sequence of events displayed in chronological order and connected by a single visual path. It can be presented vertically or horizontally depending on the layout and context. Each event includes key details such as status, time, or user or system actions, providing a clear overview of how something has progressed. The structure helps users understand sequence, context, and change over time at a glance.

## 2. Usage

### When to Use

Use a Timeline when presenting multiple related events that share a common subject but contain independent details, such as activity history, process updates, or case tracking. It is particularly effective when order and progression are important to understanding the narrative. Avoid using it for non-sequential information or when events do not have a meaningful time-based relationship.

### Do
- Use Timelines for chronological tracking of project milestones, steps, or activities
- Order events strictly in chronological order
- Use contextual colours and icons to indicate status
- Keep event content focused on the key user or system action
- Show supplementary information such as date and time in secondary areas

### Don't
- Use Timelines when events are unrelated or independent of each other
- Mix event sequences or leave them unordered
- Leave all events visually identical without distinction
- Overload events with excessive or unrelated detail
- Make dates or metadata more prominent than the event itself

## 3. Composition

The Timeline consists of the following accessories:

| Accessory | Required | Description |
|---|---|---|
| Subtitle | Optional | An optional short line of supporting text displayed accompanying the title to provide additional context or clarification about the milestone or event |
